高速ファイル検索アプリ 仕様書

Version: 1.1
更新日: 2026年10月21日
対象OS: Windows 11

---

1. 目的

Windows 11のローカルディスクを対象として、Everythingと同様の高速なファイル名検索を実現する。

機能は以下に限定する。

- インクリメンタルサーチ
- 検索結果の一覧表示
- 4列によるソート
- 検索結果からのドラッグ＆ドロップ
- システムトレイへの常駐

ファイル名検索に必要な機能だけを実装し、シンプルで高速、かつ常時利用できるアプリケーションとする。

2. 動作環境

項目| 仕様
OS| Windows 11
開発言語| C#
フレームワーク| .NET 10 LTS
UI| WPF
検索対象| "C:\" のみ
ストレージ| 内蔵SSD
ファイルシステム| NTFS
実行権限| 管理者権限
外部サービス| 不使用
データ保存| ローカル
動作形態| システムトレイ常駐

3. 機能仕様

3.1 インクリメンタルサーチ

ID| 仕様
SR-01| 画面上部に検索文字列入力欄を配置する
SR-02| 文字の入力・削除に応じて検索結果を自動更新する
SR-03| ファイル名・フォルダー名を検索対象とする
SR-04| 部分一致検索とする
SR-05| 大文字・小文字を区別しない
SR-06| メモリ上の索引に対して検索を実行する
SR-07| 検索中も画面操作をブロックしない
SR-08| 新しい検索入力が発生した場合、古い検索結果で画面を上書きしない
SR-09| 検索文字列が空の場合、結果を表示しない

3.2 検索結果一覧

検索結果は以下の4列で表示する。

列| 表示内容
名前| ファイル名またはフォルダー名
フォルダ| 親フォルダーのフルパス
サイズ| ファイルサイズ
更新日時| 最終更新日時

表示ルール：

- ファイルとフォルダーを同じ一覧に表示する。
- サイズはKB・MB・GBなどの適切な単位で表示する。
- フォルダーのサイズは空欄とする。
- 更新日時はローカル時刻で表示する。
- ファイル名・フォルダー名は省略表示可能とする。
- 列幅を変更できるようにする。
- 大量件数の表示にはUI仮想化を使用する。

3.3 ソート

ID| 仕様
ST-01| 4列すべてソート可能とする
ST-02| 列ヘッダークリックでソートする
ST-03| 同一列の再クリックで昇順・降順を切り替える
ST-04| 初期ソートは名前の昇順とする
ST-05| 検索文字列を変更してもソート条件を維持する
ST-06| サイズは数値で比較する
ST-07| 更新日時は日時値で比較する
ST-08| 同一キーの場合は内部IDなどで順序を安定させる

3.4 ドラッグ＆ドロップ

ID| 仕様
DD-01| 検索結果のファイル・フォルダーをドラッグできる
DD-02| 複数選択した項目をまとめてドラッグできる
DD-03| Windows Explorerなどの対応アプリへドロップできる
DD-04| Windows標準のファイルドロップ形式 "CF_HDROP" を使用する
DD-05| コピー・移動などの処理はドロップ先とWindows標準の操作規則に従う
DD-06| アプリ内独自のファイルコピー・移動処理は実装しない

3.5 システムトレイ常駐

ID| 仕様
TR-01| アプリ起動時にシステムトレイへアイコンを表示する
TR-02| ウィンドウを閉じてもアプリは終了せず、トレイに常駐する
TR-03| トレイアイコンのダブルクリックで検索画面を表示する
TR-04| 検索画面が既に開いている場合は最前面に表示してアクティブ化する
TR-05| 検索画面を表示した際は検索欄へフォーカスする
TR-06| トレイアイコンの右クリックでメニューを表示する
TR-07| 右クリックメニューに「検索画面を開く」「終了」を配置する
TR-08| 「終了」を選択した場合のみ、アプリを正常終了する
TR-09| ウィンドウを非表示にしても索引の差分更新を継続する
TR-10| アプリの多重起動を防止する

常駐中の動作

- ウィンドウは非表示とする。
- 検索索引はメモリ上に保持する。
- USN Journalによる変更追跡を継続する。
- ウィンドウの再表示時に索引を再構築しない。
- 終了時は索引の永続化とリソース解放を行う。

終了操作

トレイメニューの「終了」でのみ、アプリケーションを終了する。

Windowsのシャットダウンやログオフ時には、ウィンドウの通常の閉じる処理とは区別して終了する。

4. 索引管理

4.1 初期索引

ID| 仕様
IX-01| CドライブのNTFS MFT情報を取得する
IX-02| ファイル名、親ディレクトリ、サイズ、更新日時を索引化する
IX-03| ファイル・フォルダーを識別する内部IDを保持する
IX-04| ディレクトリ階層を復元できる構造とする
IX-05| 索引をローカルファイルへ永続化する
IX-06| 有効な保存済み索引がない場合は再構築する

MFT列挙情報に含まれないサイズ・更新日時などは、必要に応じて追加取得する。

4.2 差分更新

ID| 仕様
IX-07| USN Change Journalで変更を追跡する
IX-08| ファイル・フォルダーの追加を反映する
IX-09| 削除を反映する
IX-10| 名前変更・移動を反映する
IX-11| サイズ・更新日時の変更を反映する
IX-12| アプリ停止中の変更を起動時に反映する
IX-13| USN Journalの継続性を確認する
IX-14| 差分取得が不可能な場合は索引を再構築する
IX-15| ウィンドウ非表示中も索引を更新する

索引の整合性

- 索引とUSN Journalの継続位置を対応付けて保存する。
- ボリューム識別情報を保持し、異なるボリュームの索引を再利用しない。
- 再起動時に保存済み索引の有効性を検証する。
- USN Journalの継続性が失われた場合は再索引化する。
- 索引の更新中にアプリが終了しても、次回起動時に整合性を回復できるようにする。

5. 画面仕様

5.1 画面構成

シングルウィンドウ構成とする。

画面は以下の2領域で構成する。

1. 検索文字列入力欄
2. 検索結果一覧

検索結果一覧には「名前」「フォルダ」「サイズ」「更新日時」の4列を配置する。

高度な検索条件パネル、プレビュー、複数タブは設けない。

5.2 画面操作

- 文字入力に伴い検索結果を更新する。
- 列ヘッダーのクリックでソートする。
- 一覧から複数項目を選択できる。
- 選択した項目を外部アプリケーションへドラッグできる。
- ウィンドウを閉じると非表示になり、システムトレイに常駐する。
- トレイアイコンのダブルクリックで検索画面を再表示する。

6. 非機能要件

6.1 性能

ID| 要件
NF-01| 検索処理でディスク全体を走査しない
NF-02| キー入力に追従して検索結果を更新する
NF-03| 検索・ソートはUIスレッドをブロックしない
NF-04| 一覧表示にUI仮想化を使用する
NF-05| 索引更新中も検索操作を継続できる
NF-06| 索引データのメモリ消費を抑制する
NF-07| 常駐中も不要なCPU負荷を発生させない
NF-08| ウィンドウ再表示時に初期索引処理を行わない

検索応答時間、初期索引時間、メモリ使用量の定量目標は、実データ件数を測定したうえで設定する。

6.2 信頼性

- 索引ファイルの破損を検出できること。
- 索引の再構築で復旧できること。
- 存在しないファイルが検索結果に一時的に残っていても、アプリが異常終了しないこと。
- 索引更新中の異常終了から復旧できること。
- 索引保存中の終了によって既存の正常な索引を破損しないこと。
- システムトレイ常駐中も索引管理が継続されること。

7. 技術構成

コンポーネント| 役割
Search UI| WPF画面、検索入力、一覧、ソート、DnD
Tray Manager| システムトレイアイコン、表示・終了制御
Search Engine| メモリ内検索、結果抽出
Index Manager| 索引保持、追加・更新・削除
NTFS Reader| MFT情報取得、ファイル属性取得
USN Monitor| ファイルシステム変更検出
Index Storage| 索引とUSN継続位置の永続化

7.1 実装方針

- 検索エンジンとUIを分離する。
- 索引管理はウィンドウの表示状態に依存しない。
- 常駐機能は同一プロセス内で実現する。
- "System.Windows.Forms.NotifyIcon" を使用する。
- WPFの終了モードは "ShutdownMode.OnExplicitShutdown" とする。
- Windowsサービスは使用しない。
- Windows APIはP/Invokeで呼び出す。

8. 対象外機能

以下は実装しない。

- ファイル内容の全文検索
- 正規表現・高度な検索構文
- 検索対象ドライブの切り替え
- ネットワークドライブ・外付けストレージへの対応
- ファイルプレビュー
- 複数タブ
- アプリ独自のコピー・移動・削除
- ファイル内容の編集
- クラウド同期
- Windowsサービスによる常駐

10. 技術的な注意事項

10.1 NTFSの属性取得

MFTの列挙のみでは、検索結果の4列に必要な情報をすべて取得できない。

サイズや更新日時は追加のファイル情報取得を必要とするため、初期索引構築時のI/O負荷に注意する。

10.2 ディレクトリ構造

索引には親ディレクトリとの参照関係を保持する。

親フォルダーが移動・改名された場合でも、配下のファイルのフルパスを正しく構成できるようにする。

10.3 USN Journal

USN Journalはファイルの変更履歴を取得するための仕組みであり、ファイル属性の完全な情報源ではない。

変更検出と属性取得を分離する。

10.4 管理者権限

NTFSボリュームに対するMFT列挙などの操作には適切な権限が必要である。

アプリは管理者権限で実行する前提とする。

10.5 常駐とプロセス寿命

ウィンドウの表示状態とアプリケーションの生存期間を分離する。

ウィンドウを閉じても索引管理と変更追跡を継続し、明示的な終了操作またはOSの終了によってプロセスを終了する。

仕様書 v1.1 — 確定版

検索対象をCドライブのNTFSに固定し、インクリメンタル検索・4列表示・ソート・DnD・システムトレイ常駐に機能を限定する。
