## Private Bytes の段階計測

[生CSV](measurements/memory-profile-2026-10-21.csv)。301,001件の索引（ファイル300,000件＋フォルダ1,001件）、最大300,000件の結果。
実ディスクではなく、専用プロセスで合成索引を構築して測定した値です。

| 状態 | 索引件数 | 保持結果数 | Private Bytes（MiB） | Managed（MiB） | 生成行数 |
|---|---:|---:|---:|---:|---:|
| 起動直後（WPF初期化前） | 0 | 0 | 9.78 | 0.71 | 0 |
| 合成索引完成・WPF初期化前 | 301,001 | 0 | 76.68 | 55.44 | 0 |
| 検索実行中のサンプル最大 | 301,001 | 0 | 92.63 | 約71.04 | 0 |
| 検索結果を抽出・保持 | 301,001 | 300,000 | 92.63 | 71.04 | 0 |
| WPFで大量結果をレイアウト | 301,001 | 300,000 | 133.37 | 75.82 | 15 |
| UIから結果を外し、回収後 | 301,001 | 0 | 133.84 | 70.11 | 0 |
| 30回の検索・解放・回収後 | 301,001 | 0 | 144.39 | 約70.09 | 0 |

後半20回の結果解放後の Private Bytes は約140.05～150.82 MiB、Managed は約70.09 MiBで推移しました。
Private Bytes は GC の確保領域・JIT・WPF等も含み、参照解放と同時に減少する指標ではありません。
短時間の30回試験では上昇し続ける挙動は見られませんでしたが、長時間の安定性やメモリ上限を保証する測定ではありません。

プロファイルでは段階比較のため明示的にGCを実行しています。製品コードには強制GCを加えていません。
索引のみ・検索結果・UIの差分はこの測定条件でのプロセス総量の差であり、厳密なコンポーネント別割り当て量ではありません。
実プロセスの6状態は `--measure-memory` で記録でき、検索中は25msおき、常駐中はUIに触れず5分おきにサンプリングします。
