# 実機受入確認

自動テストで検証したロジックと、実際の Explorer・トレイ・OS 終了の操作確認を区別してください。
以下は手動確認の手順であり、確認済みという意味ではありません。

| 条件 | 手順 / 期待結果 |
|---|---|
| AC-01 | 初回起動で MFT / 属性取得の進捗が表示され、完了後に検索でき、ローカルに index.bin が保存される。 |
| AC-02,03 | テスト用ファイルと親フォルダーを作成し、ファイル名の一部を大小文字を変えて入力。入力・削除に追従し、空欄は0件となる。v1.3ではフォルダ自体は表示しない。 |
| AC-04 | 4列それぞれを2回クリックして順序を確認。100 B と2 KB、日付の大小も確認。入力変更後も条件が維持される。 |
| AC-05 | Ctrl / Shift で複数選択して Explorer へドラッグ。コピー / 移動の修飾キーは Windows の通常動作に従う。 |
| AC-06,07 | 専用のテスト用フォルダー内で作成・追記・改名・移動・削除を行い、通常1秒＋処理時間で反映されることを確認。親フォルダーの改名も確認。 |
| AC-08,09 | トレイから終了し、停止中にテストファイルを変更して再起動。MFT 全再列挙をせず、停止中の変更が反映される。 |
| AC-10 | テスト環境で保存済み索引の破損 / 無効な継続位置を用意して再構築を確認。通常利用の C ドライブの Journal を削除する試験は不要。 |
| AC-11 | 該当数の多い検索を実行し、入力、列幅変更、スクロールが応答する。 |
| AC-12 | 該当数の多い文字列から素早く別の文字列へ入力し、最後の入力に一致した結果だけが最終表示される。 |
| AC-13 | × を押してもトレイとプロセスが残る。 |
| AC-14,15 | トレイをダブルクリックして表示・前面化・検索欄のフォーカスを確認。最小化時にも同様。 |
| AC-16 | 非表示中にファイルを作成・改名し、復帰後に変更を検索できる。復帰時に全再構築しない。 |
| AC-17 | トレイの「終了」でプロセスとトレイアイコンが消える。次回に保存済み索引を再利用できる。 |
| AC-18 | 同じ exe を2回起動し、既存ウィンドウが前面に出て常駐プロセスが1つだけである。 |
| AC-19 | 保存後にログオフまたはシャットダウンし、終了を妨げず次回に再開できる。 |
| AC-20,21 | 非表示・表示・最小化の各状態から Win + / で表示・前面化し、検索欄への入力を確認。復帰時に全再索引しない。他アプリとの競合時はトレイ操作を継続できる。 |
| AC-22,23 | 検索欄で ↓ を押し先頭行へ移動。一覧の ↓ / ↑ で移動し、先頭行の ↑ で検索欄へ戻る。0件では検索欄に留まる。 |
| AC-24 | 一覧のどの行からも `/` で検索欄へ戻り、文字列が変化しない。テンキーの除算も同様。 |
| AC-25,26 | 同名のフォルダとファイルを用意し、ファイルだけが部分一致で表示される。 |
| AC-27 | `var/repo` が `myvar` 直下の `report` に一致し、`myreport` には一致しない。 |
| AC-28 | `var/data/repo` が `myvar/data/report` に一致し、`var/other/data/report`・`var/database/report`・`var/data/sub/report` には一致しない。 |
| AC-29 | `/var/data/repo` が `work/var/data/report` に一致し、`myvar/data/report` には一致しない。 |
| AC-30,31,34 | 一覧で Enter または修飾キーなしの左クリックを行い、既定アプリで開く。消失したファイルではエラーを表示し、検索を継続できる。 |
| AC-32 | Ctrl / Shift で複数選択してドラッグ。クリックしたファイルが開かない。ドラッグを Esc でキャンセルしても開かない。 |
| AC-33 | 右クリックで拡張子に対応する従来形式シェルメニューが開く。キャンセル・プロパティなどの実行後も検索・差分更新が継続する。 |
| AC-35 | 自動検証で ProcessRenderMode が SoftwareOnly と一致する。 |
| AC-36 | `--measure-memory` で起動し、初期索引完成・検索・大量表示・非表示の各状態を作り、CSVの件数と Private Bytes を確認する。 |
| AC-37 | 大量結果を表示しても realized_rows は表示領域付近の行数に留まる。画面サイズ変更とスクロールでも確認する。 |
| AC-38 | 計測を有効にして数時間～一日常駐し、ファイル変更・画面表示・検索・非表示を繰り返す。ウォームアップ後の同条件サンプルで一方向の増加が継続しないことを確認する。具体的な上限は件数と実測後に決める。 |
| AC-39 | 非表示中もファイル変更が追跡され、表示結果数は0となる。復帰後は検索文字列・ソート条件を保って最新索引から再検索する。 |
| AC-40 | 検索欄と結果一覧それぞれで Ctrl+1～4 を押し、名前・フォルダ・サイズ・更新日時が対応することを確認。通常の数字キーとテンキーを確認し、ヘッダーの矢印も確認する。 |
| AC-41 | 同じキーを再押下して昇順・降順を切り替える。ヘッダークリックと交互に操作しても同じ条件から切り替わり、別列は昇順で開始する。 |
| AC-42 | 検索欄からソート後はそのまま入力でき、一覧からソート後は同じファイルを選択して上下移動できる。非同期処理中にフォーカスを移した場合も完了時に移動先を維持する。検索文字列変更後もソート条件を維持する。 |

実データで計測する項目: 件数、初回索引秒数、保存済み索引からの起動秒数、代表検索の所要時間、
全件に近い検索・ソートの所要時間、検索画面表示時 / 非表示時のプロセスメモリ、アイドル CPU。
